## 目标

`insurance` 意图（用户说「我想买保险」这类）识别完成后，后端不再让模型凭空写 `plan` 字段，而是**查 `plan_shows` 表 → 在 Python 里确定性地生成 A2UI v0.9 命令 → 以 ```a2ui 围栏追加到助手回复末尾**。前端沿用现有的 `createInsuranceMockReply` 同形解析路径（提取围栏里的 `{"surfaceId","commands"}`），零新 SSE 帧类型。

---

## 一、前端契约（这次要对齐的核心）

### 1. 消息形态

助手回复 = 一句自然语言说明 + 空行 + a2ui 围栏：

````
以下是我们当前在售的 25 款保障方案，涵盖寿险、健康、年金、万能四类，您可以逐张查看。

```a2ui
{"surfaceId":"insurance_plans_7f3a91c2","commands":[
  {"version":"v0.9","createSurface":{...}},
  {"version":"v0.9","updateComponents":{...}},
  {"version":"v0.9","updateDataModel":{...}}
]}
```
````

前端**用正则提取围栏**（``/```a2ui\s*([\s\S]*?)```/``）而不是 `startsWith`，因为围栏前面有说明文字。这是你选的方案，与现有 mock 的唯一差别就是多了前面那句话。

### 2. envelope 形状

与你的 mock 完全一致：`{ "surfaceId": string, "commands": XAgentCommand_v0_9[] }`，三条命令固定顺序：`createSurface` → `updateComponents` → `updateDataModel`。

- `surfaceId`：**每轮唯一**，形如 `insurance_plans_7f3a91c2`（uuid 前 8 位）。不固定成 `insurance_plans`，否则同一会话里两轮保险问答、或前端同时渲染两个 XCard.Box 时会撞 surfaceId，第二条卡会覆盖第一条。
- `catalogId`：按你的选择用官方基本目录 `https://a2ui.org/specification/v0_9/basic_catalog.json`，但**写成后端配置项**（`app/core/config.py` 的 `plan_show_catalog_id`，可用环境变量 `PLAN_SHOW_CATALOG_ID` 覆盖），这样以后想换成 `local://plan_show_catalog.json` 不用改代码。
  - ⚠️ **这里有个必须处理的不一致**：我们用的组件名是业务专用的（`PlanCard` 等），它们不在官方基本目录里。A2UI 渲染器对「目录里查不到的组件」是按优雅降级处理的（渲染占位而不是崩溃），所以能用，但会丢校验。**前端 registerCatalog 时注册的那份目录（不管用什么 id）必须包含下面这 6 个业务组件**，否则渲染出来是占位文本。我会把这份目录 schema 写成 `docs/catalogs/plan_show_catalog.json` 交给前端直接用。

### 3. 组件契约（业务专用名，按你的选择）

| 组件 | props | 说明 |
|---|---|---|
| `PlanList` | `children: string[]` | 根容器，垂直单列 |
| `PlanCard` | `groupCode`, `groupName`, `title`, `hasSale`, `children: string[]` | 单张方案卡；`hasSale` 原样下发（"1"/"2"），是否置灰/打标签由前端决定 |
| `PlanImage` | `url`, `altText` | 方案配图，`altText` 用方案名 |
| `PlanPoints` | `items: string[]` | 卖点，来源 `contents` 按 CRLF 拆行 |
| `PlanActions` | `children: string[]` | 按钮容器 |
| `PlanActionButton` | `text`, `backgroundColor`, `color`, `borderRadius`, `action` | 两个按钮共用 |

单张卡的组件树：`PlanCard` → [`PlanImage`, `PlanPoints`, `PlanActions` → [`预核保按钮`, `正式投保按钮`]]。

### 4. 按钮与 action 契约

| 按钮文案 | backgroundColor | color | borderRadius | action.event.name |
|---|---|---|---|---|
| 预核保 | `#699bf6` | `#ffffff` | `6px` | `plan_pre_underwrite` |
| 正式投保 | `#028550` | `#ffffff` | `6px` | `plan_apply` |

两个按钮的 `action.event.context` 都带字面量（不是 `{path}`，所以点击时 X-Card 原样透传，前端 `onAction` 里直接取到值）：

```json
{"group_code":"G0264","group_name":"鸿利悠享2.0两全保险（分红型）","title":"寿险","insur_list":["AYR","AYS","AYT"]}
```

带 `insur_list` 是因为投保/预核保需要险种代码。圆角按 `6px` 定了，要更圆/更方改常量即可。

### 5. 历史消息重放

围栏**同时写进 `messages` 表的 content**，所以前端拉历史消息（`GET /api/v1/threads/{id}/messages`）时拿到的 content 里带围栏，用同一套解析逻辑就能复现卡片。

**但围栏不会进 LangGraph checkpoint**（也就是不会进模型后续轮次的上下文）。这是刻意的：25 张卡的 JSON 约 27KB / 7k tokens，如果进了对话记忆，之后每轮请求都要多烧这些 token。实现上就是「卡片只走状态 → API 出口」，模型自己写的那句正文里没有命令。

## 二、后端改动

### 新增 `app/services/plans/`（业务服务层，参照 `app/services/rag/` 的扁平函数风格）

- `__init__.py` — 导出 `list_plan_shows`、`build_plan_card_envelope`。
- `query.py` — `list_plan_shows(session) -> list[PlanShow]`：`select(PlanShow).order_by(PlanShow.title_ord_num, PlanShow.order_num)`，**不过滤 `has_sale`**（按你的选择，25 条全返回），带 `MAX_PLAN_SHOW_ITEMS = 50` 上限兜底。
- `x_card.py` — `build_plan_card_envelope(rows, *, surface_id, catalog_id) -> dict`：纯函数，无 IO，按上面的组件契约生成 `{"surfaceId","commands"}`。CRLF 拆行、`insur_list` 透传、`groupCode` 拼组件 id（`plan_G0264`）。空列表返回 `None`（调用方决定不出卡）。
- `docs/catalogs/plan_show_catalog.json` — 上面 6 个组件的 JSON Schema，前端 `registerCatalog` 直接用。

### 新增 `app/core/langgraph/agents/insurance.py`（照抄 `search.py` 的确定性子图模式）

```
START → plan_query_node → insurance_answer_node → END
```

- `plan_query_node`：`with Session(engine) as session:` 查表 → 生成 envelope → 写 `state["x_card"]`；失败只记日志并置 `None`，不打断本轮（照抄 `tavily_node` 的错误处理姿态）。
- `insurance_answer_node`：`create_agent`，中间件链复用 `_build_middleware_chain(spec, registry)`，但把 index 0 的动态提示词换成保险专用的（照抄 `search.py:152` 的 `_make_search_answer_prompt` 模式），把「本轮已下发 N 张卡」或「卡片查询失败」作为上下文注入，避免模型承诺了卡片却没卡。

### 修改 `app/core/langgraph/state.py`

`ChatAgentState` 加 `x_card: NotRequired[dict[str, Any] | None]` —— 子图写、外层图（`SupervisorState` 继承它）能读到，API 才能取到。

### 修改 `app/core/langgraph/agents/factory.py`

`build_agent_for_intent` 加分支：`spec.id == "insurance"` → 延迟导入 `build_insurance_agent(spec)`（与 search 完全同构，避免循环依赖）。

### 修改 `app/core/langgraph/prompts/system_chat.py`

重写 `INSURANCE_PROTOCOL_PROMPT`：从旧的 `{"content","plan":null}` JSON 协议改为**纯自然语言**协议（2–3 句，可追问年龄/预算/保障需求；不得编造产品、保费、条款；已下发卡片时不要再逐条罗列产品）。旧的 `plan` 字段契约随之作废——前端本来就重做这块，但这是一处**要同步的契约变更**。

### 修改 `app/core/langgraph/intent/registry.py`

- `insurance` 的 examples 补一条 `"你们现在有哪些保险产品在售"`。
- `general` 的 examples 里 `"帮我介绍一下你们的产品"` 改成 `"介绍一下你们公司"`——它现在与保险产品清单意图重叠，会把「你们有哪些产品」误路由到 general。

### 修改 `app/api/v1/chat.py`

1. 流结束后（`finally` 里，发 stop 帧**之前**）读一次图状态：`state = await agent.aget_state(config)`，取 `state.values.get("x_card")`。
2. 有卡片 → 先 `yield` 一个 `delta.content` 帧，内容为围栏块，再发 stop 帧和 `[DONE]`。前端拿到的正文流与历史重放完全同形。
3. 落库时把同一段后缀拼到 `assistant_fields["content"]` 上（不加到 checkpoint 消息里，见契约第 5 点）。
4. 顺手加防御性判断：`custom` 分支目前无条件读 `chunk.content`/`chunk.additional_kwargs`，遇到非 `AIMessageChunk` 的 payload 会抛 `AttributeError` 并被吞成 `{"error":...}` 帧。加 `isinstance` 判断跳过未知 payload（约 3 行，不影响现有 token 流）。

### 文档

- `docs/a2ui-plan-cards.md`：envelope 形状、组件契约、两个按钮的颜色/action、围栏正则、历史重放说明、`catalogId` 与目录注册注意事项——给前端同事看的一份。
- `docs/llm-service.md` 补一段保险意图的确定性管线说明。

## 四、明确不做（本次范围外）

- 「组合」分类（titleId=4）源数据为空、表里没有行；单列流不需要 Tab 列表，因此不受影响。
- 详情页 URL：`plan_shows` 没有该字段（只有 `products` 表有 `terms_url`，且与方案不是同一套键），两个按钮只回传方案标识，不做跳转。
- 25 张卡用「字面量 props」生成（约 27KB），不用 `List` 模板迭代（模板模式只要 ~1KB，但要求前端实现模板渲染 + 相对路径绑定，留作后续优化）。
- `state.py` 与 `docs/llm-service.md` 里描述但从未实现的 `{"type":"intent"}` 广播不在本次处理。

## 五、实现后需要你核对的一点

`catalogId` 用官方基本目录 URL、组件用业务专用名，这两件事本身有矛盾（业务组件不在官方目录里）。我按你的选择实现并做成配置项 + 附上目录文件，但如果前端 `registerCatalog` 注册的 id 不是这个官方 URL，卡片会渲染成占位。实现完我会把「前端要注册什么」写进 `docs/a2ui-plan-cards.md`，你核对一下和你前端的实际注册方式是否一致；不一致的话改一个环境变量就能对齐。
